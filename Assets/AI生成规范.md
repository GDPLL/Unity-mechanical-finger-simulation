AI生成代码必须遵循本规范文档

注释:
注释不要加，新增，添加，和原来...怎么样这类更新描述词，多余且造成阅读成本增加
注释不要擅自添加注释格式，如// =========== 注释内容 ========= 和大量多余文本的///<summy>的注释类型，注释只做最简单的功能说明，每个方法和一片字段范围内都必须有功能说明，说明传入数据作用,非必要不超过15个字，至于///<summy>类型注释必须在操作着明确说明添加时才可添加
关键方法涉及到功能内核的关键方法必须添加注释并标记出来功能作用
字段组和方法注释在上一行添加，字段注释在字段本行后添加
禁止多余形容词和过度解释，减少使用（）和  ： 的次数
典型错误案例
{
	// 记录原始后坐力（肩射减后坐力恢复用）											->过度解释
	// ===================== 原有：初始化 =====================	->非法注释方法与不必要的符号
	// 【新增】开局按腰射外圈起步													->非法更新注释
	// 开火点：没配枪口就退回枪身上方 1 米（和原来 Shoot() 里的兜底一致）				->过度解释与不必要的符号
	// 一种姿态对应的一组参数（Inspector 里会折叠成一组）							->非功能说明的过度解释
	// ===================== 原有：基础参数 =====================	->非法注释方法与不必要的符号
}
过度解释案例
// 判定目标是否还在"当前姿态的外圈"里
// 目标坐标由外界给，这里只做夹角计算，不去场景里找东西
改为
//  判定目标是否还在当前外圈
严禁/目标坐标由外界给，这里只做夹角计算，不去场景里找东西/这种过度解释



方法:
所有功能实现以最简单方法实现，不擅自添加各类处理方法，只做最简单的方法实现，必要时再提醒操作者有更优方案，否则一律只用最简单功能实现方法
对于功能组合类型方法涉及到拆解且操作者没有提供明确方案必须在生成时就和操作者询问具体方法方案并提供多种方案组，未获得反馈时一律用最简单且添加方法最少的方案
任何为空判定都必须有debug.error输出，不能直接忽略或退出，相关错误日志格式为"脚本名|对应方法|错误原因"

字段与变量：
除功能实现时的本地变量，用于计算的当前缓存变量，功能引用的外部变量，非必要不添加其他变量
